# Second review corrections for kuu 0.10.0

Follow-up to `build/review2-0.10.0.md`, covering its 25 findings and three
documentation/schema discrepancies. Changes remain in the working tree on top
of the first correction pass; this does not publish a new release.

| Finding | Correction |
|---|---|
| 1 | Each pending stdin write owns stable bytes; completed input storage is reused. A native fixture checks ownership and bounded capacity through repeated completions. |
| 2 | Whole-output and unfinished-line reads return recoverable `PROC toobig` at the unread-byte window, preserving every byte instead of deadlocking. |
| 3 | Ledger enumeration/read errors propagate; unreadable predecessors prevent appends with a warning. Capabilities distinguishes unreadable history from broken contents and verified emptiness. |
| 4 | Checker traversal errors become read findings; module inventories expose `complete/errors`, and capabilities exposes `modules_complete/module_errors`. |
| 5 | Tool declaration caches last for one check operation, so post-fix and later checks see current manifest contents. |
| 6 | A Lua to-close owner frees native HTTP construction resources on ordinary validation errors and accessor exceptions, then hands ownership to the worker before yielding. Method/type validation returns domain errors; temporary URL values stay rooted during validation. |
| 7 | The cookbook NDJSON wrapper rejects truncated capture before parsing a valid prefix. A regression executes the published code unchanged. |
| 8 | Failed log formatting drops the whole record and increments `dropped`, preserving JSON mode. |
| 9 | Dry-run JSON uses the same UTF-8 sanitation as other reports. |
| 10 | Numeric stream reads return an available prefix up to the requested size. |

The checker manual now describes declared-only scopes accurately, distinguishes
static findings from errors also rejected at runtime, and matches the uniform
`check.file` result shape, including `tools` on read failures.

Integration also exposed an adjacent stream-reader race: notification released
the single-reader reservation before the waiting coroutine resumed. A competing
reader could steal its bytes and manufacture EOF; closing first could still let
it return data. The reservation now lasts through the continuation, and close
wakes it once with `PROC closed`. A deterministic native fixture and the real
two-stream reproduction cover both outcomes.

Behavior choices: stream `maxout` is an exact unread-byte window. A whole-output
read can return `toobig` even for output exactly that size when EOF has not yet
been observed; numeric/`some` reads recover the bytes. `lines()` and `err_lines()`
raise read errors instead of silently ending iteration. Stream `maxout=0` is
rejected because it cannot make progress. Watch events are consumed once by
competing readers, rather than broadcast. JSON logging counts an unrenderable
record as dropped rather than substituting plain text. Ledger verification
omits `records` when it cannot establish a count.

Validation completed successfully. Isolated helper cases passed 186 checks;
checker/ledger/capabilities/task cases passed 312. Real Windows sharing-lock
replays now report incomplete checks and unreadable history, and refuse an
unchained append without failing the task. HTTP/cookbook/payload integration
passed 106 checks. Authored Lua, tools, and test cases pass `kuu check` with
zero errors and warnings. The final long-path replay passed all four checks;
the process/filesystem cases passed 226 checks in an isolated harness. Original
stdin retention stayed near 2.2 MB after both 256 and 512 chunks, and twenty
rejected 4 MiB HTTP requests grew private memory by only 16 KB after GC. The
full gate passed with 1,589 checks and zero failures normally (51.8 s) and under
AddressSanitizer (86.7 s). Native static analysis passed, as did 10,000 fuzz
cases per family for each of three seeds (1, 12648430, and 3735928559). The
soak completed 27 rounds in 61 s with zero failures, a handle delta of -3, and
a private-memory delta of +2.3 MB. The established `--help` redeclaration
diagnostic remains compatible while the positional-help bypass is closed.
The real reader-race replay now returns `PROC busy` to the competing reader and
`PROC closed` to a reader whose child closes before it resumes.
